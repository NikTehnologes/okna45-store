## 1. Сначала установка / ремонт / публикация

1. Сохраните Notes/черновики, личный backup flash, закройте USB editors.
2. Распакуйте **[Okna45-0.2.6.zip](../0.2.6/Okna45-0.2.6.zip)**. В **[Windows updater](../tools/Okna45-Updater.exe)** выберите **[папку с os-files.json](../0.2.6/Okna45-0.2.6/)** и Pico COM либо отдельную папку flash, не RPI-RP2.
3. Backup только заменяемых ОС-файлов/баз — `%USERPROFILE%\Okna45-backups\...\`; не весь user flash. `repo` не копируется, существующие settings/notes/scripts/apps/data/repo не удаляются. Modified drivers/recovery/OS требуют разрешения.
4. С 0.2.4/старше нужен новый host updater или USB bootstrap: старый Store не знает `.oba`. Установленная 0.2.5 принимает исправление system 0.2.6 штатно. Оба **full канала 0.2.6** подготовлены; software source bytes прежние, новый контейнер синхронизирует baseline.
5. Host update не whole-device atomic transaction. Pending journals сначала recover; при USB/power loss не загружайте mixed OS, выполните **Restore** с `host-update.json`. Не подделывайте system/software/host baselines.

**[Подробная установка/restore](GUI_OS_026.md)**, **[SIN/bootstrap/flash](UPDATES.md)**. Для manual Pages upload: содержимое **`github_store/docs/`** в существующий root либо `/docs`, сохранить все старые blobs/packages/downloads. **[Точный список](../PUBLISH_FILES.txt)**, **[SHA256](../SHA256SUMS.txt)**. Project/flash/пароли/UUID/histories/signing keys не публикуйте; `catalog.json` храните локально. Агент сайт не изменял.

## 3. Почему была неподвижная заставка и что исправлено

Пользователь сообщил: на экране только первый кадр. Старый player проверял 20-ms deadline **после** decompression/RGB565 conversion и отбрасывал подготовленный tile. Если каждый decode опаздывал, SPI не получал ни одного обновления. Короткое воспроизведение с искусственным **25-ms decode**: initial 60 tiles, **0 writes после initial**, при этом timeline завершался. Поэтому прежнее наблюдение «boot завершён / desktop активен / player unloaded» не было доказательством движения — это исправлено в проверке.

В **0.2.6**:

- **ILI9341 GRAM хранит фон.** Полный первый экран — один раз. Затем player сравнивает независимые предыдущий/целевой sparse states и отправляет **только действительно изменившиеся горизонтальные pixel runs**, включая восстановление старых pixels. LCD readback, full framebuffer в Pico RAM и повторное base decompression не нужны.
- Готовый tile **дорисовывается даже при пересечении deadline**. Между commits кадр снова выбирается по текущему elapsed time; просроченные frames не ставятся в очередь. Rotating cursor предотвращает starvation нижних tiles.
- Если устройство слишком медленно, возможны частичные frames/пропущенные показы, но не гарантированное отбрасывание всей анимации. Завершение последнего tile может добавить небольшой overrun. Nominal 50 FPS не равно измеренной скорости Pico.

Изображения/asset **не менялись**: только выбранный `LoadAnimation.gif`, **320×240 / все 96 stored frames / удалено 0**; 95 задержек по 20 ms, одна 40 ms; **1940 ms/цикл × 5 = 9700 ms** после initial draw. Source SHA256 `692929a884d6e06952f461200e4632f47c7d6ecd542003343b15516771a093b6`. Исключённый `_ORIG` не читался в этой сборке/проверке. Старое сравнение GIF сохранено: [отчёт о сжатии](gif-compression-2026-11-25.md).

RGB332 — верхние 3/3/2 bits, full-range 8×8×4 levels без dithering; согласовано с [GIF-превью](../boot-animation/rgb332-fix-2026-11-25/LoadAnimation-RGB332-preview.gif). OBA2 **17183 bytes**, RGB565 review **32297**: экономия **15114 / 46,8%**. Обе прежние review deliveries сохранены.

## 4. RAM и flash без подмены измерений

| Объект boot player | Payload bytes |
|---|---:|
| Один рабочий buffer, две sparse RGB332 states / in-place RGB565 | **2560** |
| RGB332 → RGB565 palette | **512** |
| Dirty bit map | **160** |
| Native DEFLATE window | **512** |
| Resident ends/tiles/masks/state IDs | **1868** |
| Streamed indexes, не resident целиком | **5912** |
| Наибольший compressed chunk | **268** |

Это **не полный MicroPython heap**: bytecode/native code, objects, inflater, filesystem и temporary slices имеют overhead. Desktop/apps ещё не импортированы во время animation. File/buffers/player unload, GC; потом прежняя **одна RGB565 stripe 5120 bytes** desktop. Распакованных GIF directories/frames/full framebuffer на Pico нет. При unsupported native decoder/corrupt/missing asset boot пишет USB warning и переходит в desktop.

Runtime **48 files / 279896 source+asset bytes**. Если каждый file округлять до 4096, **409600 bytes**, ниже **420000** на **10400**. Это **не LittleFS measurement и не RAM**. Пользовательский filesystem ~800000 bytes после MicroPython; сохранённые legacy files/apps/data/settings, downloaded SIN/staging отдельно. Guest full staging может не помещаться: не стирайте данные для обхода, используйте host updater, который переносит по одному ОС-файлу.

## 5. Короткие проверки

- **23 focused tests** boot/GUI/distribution прошли за **3,921 s**, без browser/full integration/device/network calls.
- Все **96 decoded RGB332 images**, arbitrary skipped/reversed selections совпадают с выбранным GIF на формате дисплея. LCD regression отвергает отправку **любого неизменившегося pixel**. Slow-decoder regression теперь пишет изменения/восстанавливает pixels и вращает cursor.
- Один offline boot с original driver и paced **моделью Pico**: **36 различных LCD states**, **17833 changed pixels / 4086 sparse writes / 581 committed tiles** после initial. Playback **9702 ms**, до desktop **12,569 host seconds** с initial display/CPU pacing. Desktop 0.2.6 активен, boot_error отсутствует, splash/decode modules unloaded. [JSON наблюдения](2026-11-25-boot026-observation.json).
- Первый старый fast-observer result 0.2.5 сохраняется для истории, но **не использован как подтверждение анимации**. Предыдущие fixes observer `micropython.const`/partial import race сохранены.
- PyInstaller updater/Windows Messenger и Gradle assembleDebug ранее завершились успешно; файлы actual EXE/APK с hashes. Ручная проверка Messenger на Windows/телефоне и live-server checks не выполнялись. Работу updater и ОС на реальном железе пользователь подтвердил после проводной установки.
- [Preservation audit](2026-11-25-preservation.json): 127 исходных protected paths, единственная изменённая delivery alias — updater EXE, прежние bytes сохранены как `Okna45-Updater-before-0.2.5.exe`; **57 files/ZIP 0.2.5**, **73 old Store blobs/packages/downloads** сохранены без изменения. Audit coverage не заменяет snapshot всего пользовательского flash.

## 7. Что не подтверждено

**Базовая установка, updater и запуск ОС подтверждены пользователем на реальном железе.** Не измерены actual FPS/heap/TLS/LittleFS/power-loss/recovery; версия MicroPython и отдельная проверка анимации/native decoder не сообщены. Это не исчерпывающий тест всех функций и не доказательство отсутствия ENOMEM при сетевой нагрузке. При повторном `ENOMEM`/allocating 2344 bytes нужны полный USB traceback, MicroPython/installed versions и `gc.mem_free()` после Ctrl+C. `zerobook/urequests.py` отсутствует: требуется compatible network library, её flash/RAM учитываются отдельно. MicroSD добавляет storage, не RAM; агент SD GPIO/writes не выполнял.

EXE без publisher signing; Android debug APK, production signing/release не проверены. Дополнительные device/phone/live messaging и AI checks требуют пользовательского действия либо отдельного разрешения; агент устройство не прошивал.
